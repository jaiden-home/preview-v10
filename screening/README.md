# screening/ — A 股均线多头全池筛选工作区

单脚本离线任务：对**沪深主板 + 创业板**全池 A 股执行「**或关系**」技术筛选——① 最新收盘价 > MA30 且 MA30 > MA60 连续 ≥ 15 个交易日，**或** ② 最新交易日当日形成 B 点（`docs/SIGNAL_RULES.md` 第一节形态口径，不含持仓状态约束）（排除 ST/\*ST 与上市不满 1 年的次新股），结果按基准日累积缓存为 JSON，并生成自包含 HTML 批次视图。

与 `src/app/screener/`（网页版条件筛选器）相互独立：本工作区为命令行离线任务，股票池覆盖全部主板/创业板代码段，支持"连续 N 日"类条件。

## 目录结构

```
screening/
├── README.md                # 本说明
├── screen.mjs               # 唯一脚本：筛选 + 缓存 + 生成 HTML 视图
├── index.html               # 批次视图（生成物：数据内嵌，双击即开、离线可用）
└── data/                    # JSON 缓存（按筛选基准日累积归档，互不覆盖）
    ├── YYYY-MM-DD.final.json  # 该基准日权威结果：统计漏斗 + 命中清单（stats.lastTradeDate 为批次最后交易日，asof 逢休市时两者不同）
    └── YYYY-MM-DD.probe.json  # --probe 试跑输出（不写正式缓存）
```

## 快速开始

```bash
# 执行筛选（默认今天为基准日；全池约 4,600+ 只，约 10–15 分钟），跑完自动生成/更新 index.html
node screening/screen.mjs 2>&1 | tee screening/data/$(date +%F).run.log

# 查看：双击打开 screening/index.html
```

先小规模试跑验证环境（约 1 分钟，不写正式缓存）：

```bash
node screening/screen.mjs --probe
```

## 参数

| 参数                | 说明                                                                                           | 默认              |
| ------------------- | ---------------------------------------------------------------------------------------------- | ----------------- |
| `--asof=YYYY-MM-DD` | 筛选基准日（决定 K 线窗口右端与次新判断基准，不可晚于今天）                                    | 今天              |
| `--fast`            | 高速模式：直连域名 + 并发 8（默认为保守模式：仅 proxy 端点 + 并发 4 + 300ms 节流，防上游限流） | 关闭              |
| `--force`           | 同 `--asof` 的缓存已存在时强制重新抓取                                                         | 关闭              |
| `--out=DIR`         | 结果 JSON 输出目录                                                                             | `screening/data/` |
| `--probe`           | 小规模试跑（前 3 批报价 + 5 只个股，输出 `*.probe.json`，不生成 HTML）                         | 关闭              |

## 缓存策略（核心）

- **累积不覆盖**：每个基准日一份 `data/{asof}.final.json`，不同日期互不影响——历史批次永久保留；
- **复用不重写**：同 `--asof` 重跑且缓存已存在时，脚本直接复用 JSON、只重建 HTML（`--force` 才重新抓取）；
- `index.html` 是可再生的只读视图：内嵌全部批次数据，双击打开即可，无需起服务。

## HTML 视图（index.html）

- 页面固定展示**最新批次**；顶部 meta 行显示批次总数、当前基准日与命中概况；
- **批次概览**：统计卡分「结果统计」（命中/可评估/命中率）与「排除条件」（ST/\*ST、次新、退市/无行情、长期停牌·K 线不足）两组；
- **概念板块热力图 + 点击筛选（统一腾讯体系，treemap 形态）**：标准热力图（Squarified treemap）——**矩形面积 = 板块当日成交额**（市场资金体量，一眼看出板块大小），**颜色 = 板块当日涨跌幅**（红涨绿跌，按当日最大幅度归一的连续色标，悬浮显示详情与领涨股）。个股概念（`plateNew`）与板块行情（`getRank`）为同一腾讯编码体系，已验证 5310/5310 完全匹配；显示命中股覆盖的标准概念板块全量（排除动态统计板块与未覆盖板块），**点击色块可多选概念——表格按并集过滤（命中任一选中概念即通过）**，再次点击取消单个，"清除筛选"清空。缓存：`data/concepts.cache.json`（个股概念，跨批次）与 `data/board-heat.cache.json`（板块行情全字段，当日有效，4 次分页请求）；
- **筛选结果**：当前批次命中清单（序号/代码/名称/均线开口比/符合天数/连涨天数/连涨+/快速反转/最近买入点/最新交易日），支持搜索与热力图概念点击筛选叠加；默认按符合天数降序，「最近买入点」列表头可点击按日期降/升序切换；
- **批次切换与对比 UI 均暂未实现**，但数据层已就绪：`index.html` 内嵌的 `BATCHES` 数组含全部批次（`hits` 含 `code/name/lastDate/lastClose/ma30/ma60/runDays`），跨批次按 `code` 关联即可计算 Δ 天数、新增、掉出，未来扩展直接消费 `data/` 下的累积缓存或页面 `BATCHES`。

## 概念数据（concepts）

结果表「概念」列与板块热力图同属**统一腾讯体系**：

1. **个股概念**：腾讯 `plateNew` 个股板块接口（`data.concept` 列表），与板块行情 `getRank` 为同一编码体系（概念 id ↔ 板块 code），保证"个股概念 ⊆ 概念板块-市场行情列表"完全匹配；
2. **两级缓存**：`data/concepts.cache.json`（逐股概念持久缓存，跨批次复用——同一只股票只抓一次）→ 未命中才逐股低速抓取（串行 + 700ms 抖动 + 指数退避 + 连续失败 5 次中止断点续存）；
3. **板块行情**：`data/board-heat.cache.json` 当日有效（4 次分页请求拉全量 804 个板块）；
4. **刷新**：删除对应缓存文件后重跑 `screen.mjs` 即可。

## 筛选口径（摘要）

- **范围**：沪主板 600/601/603/605，深主板 000/001/002/003，创业板 300/301/302；科创板、北交所、B 股不含；
- **排除**：名称含 `ST` 的全部风险警示股；窗口内行情首日距基准日不足 365 天的次新股（上游无上市日期字段，属近似口径）；退市/无行情标的（日 K 为空，多为已退市残留代码）；长期停牌标的（非次新但窗口内 K 线不足 31 根，两条命中条件都无法验证）。后两类均为保守排除；
- **条件（或关系）**：① 最新收盘价 > MA30，且 MA30 > MA60 自最新交易日向前连续 ≥ 15 日（含当日，MA 为前复权收盘价算术平均）；或 ② 最新交易日当日形成 B 点——三日强涨（每日最高 ≥ 前日 × 0.999 且收盘 > 前日收盘）+ 第 3 日收盘 ≥ MA30 + 动能保护（`R2+R3 ≥ 50%×R1` 且 `R3 ≥ 15%×R2`），纯形态口径；
- **字段**：连涨天数（最新交易日收涨时向前连续上涨的交易日数，未收涨为 0）、连涨+（连涨跨批次未中断的保持计数，`streak-state.json` 持久化：首跑为 0，之后每次跑数仍连涨且天数不减则 +1，中断归 0）、快速反转（B 点窗口首日收盘 < MA5，即自 5 日均线下方连涨出 B 点）、最近买入点（最近一次 B 点形态成立日，不限当日；页面表头可点击按日期降/升序排序）；
- **盘中口径**：腾讯 K 线接口盘中不返回当日未收盘 bar。脚本以批量报价（`qt.gtimg.cn`，零新增请求域）合成当日 bar——报价时间戳落在基准日即视为当日有行情，**当前价视同收盘价**（当日最高作 bar 最高价），因此盘中跑数与收盘后口径一致；停牌股报价时间戳为旧日期，自然不合成（沿用其停牌前末根 bar）；
- **修改条件**：调整 `screen.mjs` 中 `evaluate()` 的参数与 `SEGMENTS` 即可（如改 MA20/MA60、改连续天数、收窄板块）。

## 已知问题与对策

- **上游限流（HTTP 501）**：腾讯 `web.ifzq.gtimg.cn` 高并发拉取会触发限流。脚本**默认保守模式**：仅走 `proxy.finance.qq.com` 备用入口 + 并发 4 + 300ms 节流（约 11 只/秒、实测稳定零失败；`--fast` 恢复直连并发 8）。另有全局冷却与主跑后失败清单低速补跑（并发 2 + 300ms 节流）。若 `stats.stillFailed` 仍非空，等待几分钟后 `--force` 重跑该 asof 即可；
- **前复权精度**：不同入口（fqkline 500 天窗口 vs newfqkline 640 根）在除息日附近可能存在 ~0.001 的 MA 差异，不影响 30 日连续性判定；
- **退市残留**：报价接口对已退市代码仍返回名称（如邯郸钢铁），脚本以"日 K 为空"识别并排除。
